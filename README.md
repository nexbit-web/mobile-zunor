# Zunor — мобильное приложение

iOS и Android. Отдельный git-репозиторий в рабочей папке `zunor/`. Бэкенд —
сайт из соседней папки `../web`: его `/api/*` и вход `/api/auth/*`.

## Стек

| Что         | Чем                                                                                                                         |
| ----------- | --------------------------------------------------------------------------------------------------------------------------- |
| Платформа   | **Expo SDK 58**, React Native 0.88, React 19.3, New Architecture                                                            |
| Компилятор  | React Compiler — мемоизация без `useMemo`/`useCallback` вручную                                                             |
| Навигация   | Expo Router: маршруты-файлы в `src/app`, типизированные ссылки, **системные вкладки** (`NativeTabs` — Liquid Glass на iOS 26) |
| Стили       | **Uniwind** — Tailwind 4 для React Native; цвета — те же токены, что в кабинете сайта (`src/global.css`)                    |
| Данные      | TanStack Query: кэш, повтор, догрузка, обновление при возврате в приложение и при появлении сети                            |
| Вход        | better-auth `~1.6.34` + `@better-auth/expo` (та же версия, что на сайте): сессия в SecureStore                              |
| Иконки      | Hugeicons Stroke Rounded — тот же набор, что на сайте; во вкладках — системные (SF Symbols / Material)                      |
| Картинки    | `expo-image`                                                                                                                |

## Запуск (dev)

Сборки не нужны. Сайт (бекенд) — либо тестовый деплой на Vercel, либо
локальный `../web`.

**Против Vercel** (сейчас так): в `mobile/.env` —
`EXPO_PUBLIC_API_URL=https://zunor-ten.vercel.app`. Локальный сайт не
нужен.

**Против локального сайта:** убери `EXPO_PUBLIC_API_URL` и запусти сайт
так, чтобы его видел телефон: `cd ../web && npm run dev -- --host`. Адрес
приложение возьмёт само: тот же компьютер, порт 5173 (`src/lib/config.ts`).

### В браузере

1. `cd mobile && npm run web` — откроется `http://localhost:8081`.
2. В Chrome: F12 → значок телефона (Device Toolbar) → iPhone, чтобы
   смотреть в размере телефона.
3. Войди почтой и паролем от аккаунта на том сайте, куда смотрит
   приложение.

С телефона в браузере — `http://<IP компьютера>:8081` (IP — строка
«Metro waiting on exp://…» в терминале); нужен открытый порт 8081, см.
брандмауэр ниже.

Как это устроено: в браузере приложение ходит в `/api/*` на свой же адрес,
а Metro пересылает запросы на сайт (`scripts/dev-api-proxy.js`). Напрямую
мешали бы CORS и cookie. Сессия в браузере — cookie сайта, а не
SecureStore.

Браузер — **для проверки интерфейса и данных**. Не похоже на телефон:
вкладки — веб-версия, а не системные (на iOS нет Liquid Glass), большие
заголовки и жесты назад — только в нативе. Окончательно смотрим в Expo Go.

### В Expo Go

`npm start` → отсканируй QR-код (на iPhone — камерой, на Android — в
Expo Go). Телефон и компьютер — в одной сети. Против Vercel на нём нужна
переменная `ZUNOR_EXPO_GO=1` (иначе сайт не примет вход из Expo Go).

**Если телефон не подключается** — почти всегда виноват брандмауэр
Windows. Открывай только два порта dev-режима (сайт 5173 и Metro 8081) и
только для частных сетей. В PowerShell от администратора:

```powershell
New-NetFirewallRule -DisplayName "Zunor dev" -Direction Inbound -Protocol TCP -LocalPort 5173,8081 -Action Allow -Profile Private
# убрать, когда не нужно:
Remove-NetFirewallRule -DisplayName "Zunor dev"
```

**Безопасность dev-режима:**
- `--host` делает сайт видимым **всем в этой сети**. Dev-сервер не
  защищён, как прод, поэтому только в своей сети (своя точка доступа,
  домашний Wi-Fi). В кафе и коворкинге — без `--host`.
- В dev всё идёт по `http`: пароль и сессия передаются по сети без
  шифрования. Входи тестовым аккаунтом, а не админским.
- Сайт в dev работает с той базой, что указана в `web/.env`. Если это
  боевая база — всё, что делаешь в dev, происходит с настоящими
  данными. Для разработки лучше отдельная ветка базы в Neon.

Изменил `app.json`, `metro.config.js`, `global.css` или пакеты и что-то
не подхватилось (например, «Requiring unknown module») — `npx expo start -c`
(с очисткой кэша).

**Веб — только в dev** (`web.output: "single"` в `app.json`): обычное
одностраничное приложение, без серверного рендера. Раньше там был
серверный рендер, и Metro падал по памяти — `output: "server"` не
возвращать. Собирать веб для публикации не нужно: сайт — это `../web`.

Первое открытие собирается несколько минут, дальше берётся из кэша. Если Metro всё же упадёт с «heap out of memory», запусти с
бóльшим лимитом памяти:
`$env:NODE_OPTIONS="--max-old-space-size=4096"; npx expo start -c`.

Проверки: `npm run typecheck`, `npx expo-doctor`.

## Что уже есть

```
src/
├── app/                       маршруты (каждый файл — экран)
│   ├── _layout.tsx            корень: вход или вкладки — по сессии (Stack.Protected)
│   ├── sign-in.tsx            вход почтой и паролем; регистрация — на сайте
│   └── (app)/
│       ├── _layout.tsx        системные вкладки по роли
│       ├── (jobs)/            «Мої заявки» клиента / «Стрічка» мастера + экран заявки
│       ├── orders/  messages/  notifications/   пока «незабаром»
│       └── profile/           профиль, анкета не заполнена → на сайт, выход
├── components/                кнопка, поле, карточка заявки, пустые состояния
├── lib/                       config (адрес API), auth, api (запросы с сессией), theme
├── shared/                    КОПИИ кода сайта: подписи услуг, день уборки, форматы дат
└── global.css                 Tailwind + палитра
```

- Заявки и лента — настоящие данные: `GET /api/jobs/feed?view=mine|feed`.
  Правила ленты (волны рассылки, расстояние) считает сервер.
- Экран заявки — `GET /api/jobs/[id]`, тот же доступ, что на сайте.
- Светлая и тёмная тема — по системной.
- Значок и заставка — временно иконка сайта (512 px). Для сторов нужен
  значок 1024 px.

## Что дальше

**Сервер (`../web`):**
1. ~~Вход из приложения~~ — готово: на сайте плагин `expo()`, а
   `zunor://` (и `exp://` в dev) в `trustedOrigins`.

   лоадеры страниц.
5. better-auth 1.7 — отдельная задача: нужна миграция `Account.issuer` и
   дозаполнение данных. Обновлять **вместе** на сайте и в приложении.

**Приложение:**
- заказы;
- чаты (Pusher);
- уведомления и push;
- пропозиция мастера;
- заявка через чат с Zunor (поток читается через `expo/fetch`);
- вход через Google и Apple.

## Правила

- **Общий код с сайтом — копией в `src/shared/`**, в каждом файле указано,
  откуда взято. Импорт `../web/...` не работает: сборка EAS клонирует
  только этот репозиторий. Поменялось на сайте — поменяй копию в той же
  задаче.
- **Контракт API:** на сервере поля только добавляются, поэтому новые поля
  в типах `src/shared/*` — опциональные.
- **Цвета — только в `src/global.css`.** Где `className` не доходит
  (вкладки, шапки, иконки), используй `useColors()` из `lib/theme`: он
  читает те же переменные.
- **Тексты интерфейса — украинский**, как на сайте.
- **Пакеты с нативным кодом ставь через `npx expo install`**: он подбирает
  версию под SDK.
